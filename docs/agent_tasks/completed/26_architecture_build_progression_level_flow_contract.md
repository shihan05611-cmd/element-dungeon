## 3. 必须冻结的领域契约

实现契约必须覆盖：

1. `RunFeatureMode` 或等价的 `DISABLED / OBSERVE_ONLY / ENABLED` 模式，模式在开局冻结；正式原型中角色成长与遗物为 `DISABLED`，不能靠 UI 隐藏冒充停用。
2. RunSession 对梦尘余额、技能拥有、主动技能等级、累计实际升级支出、七槽配装和局内阶段的唯一权威；静态内容配置与运行态记录分离。
3. 主动技能购买后为 Lv1；每个主动独立等级；升级价格、最大等级和每级效果数据驱动；通用等级不得改变 SP、全局反应、冷却、槽位或技能行为。
4. 主动升级重置只返还 `floor(累计实际升级支出 × 70%)`，购买价永不返还，等级回到 Lv1；重复请求、重放和陈旧快照不能重复退款。
5. 被动第一版无等级；四个被动槽各自注册一次且不存在重复注册、重复卸载或跨房丢失。
6. 商店中的购买、升级、重置和装配分别为显式、原子、可拒绝、可幂等的权威事务；一次成功动作对应清晰的 revision 和通知次序，UI 不拥有规则。
7. 离开商店不再提交属性或二次提交配装；按钮语义为“离开商店/继续前进”。

契约中需给出建议的数据对象、命令入口、结果/拒绝原因、revision 变化、通知顺序、存档/快照字段和迁移默认值，但不得在任务 26 中实现它们。

## 4. 必须冻结的基础关卡流程

目标是低精度但真实可玩的两层六战斗节点流程。实现契约必须给出唯一、可测试的节点表和状态转换图，并满足：

- 同一个权威 RunSession 跨房、商店、路线和结算持续存在，不能通过静态变量或 UI 草稿拼接一局；
- 至少包含入口战、路线战、层主精英、构筑验证战、收束战、最终 Boss 六个战斗节点；Boss 首版可使用更强的现有敌人/配置占位，不要求精细 Boss 美术与多阶段机制；

- 至少两次二选一路线，门牌公开奖励/资源、遭遇、环境和风险信息；选择会实际决定下一房配置，不能只改按钮文案；

- 普通房结算梦尘并进入路线或商店，不生成免费技能/遗物；最终 Boss 胜利直接进入结算；
- 结算至少显示通关/失败、房间进度、梦尘收支和最终构筑，并能开始新一局或返回入口；
- 运行失败、重复房间完成、陈旧路线选择、重复结算和场景切换失败都必须有权威保护。

需要明确建议持久流程协调者、房间配置、房间实例和 UI 的职责边界；默认不得新增大型全局 Autoload，若确有必要必须写出理由、生命周期和测试替代方案。
