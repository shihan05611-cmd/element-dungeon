# 任务 19：战斗 HUD 与三选一奖励布局竞品研究

状态：ACCEPTED
负责人：UI Research Agent
依赖：任务 12、13、16～18 已验收

## 1. 任务目标

联网研究《死亡细胞》《哈迪斯》《暖雪》《小骨：英雄杀手》的战斗 HUD 与奖励选择界面，分析其生命、资源、技能槽、状态与三选一奖励的信息层级和空间使用方式。结合当前元素地牢 1152×648 实际界面，提出三套原创布局方案。

本任务只输出研究与设计文档，不修改代码、场景、资源或正式数值；不得复制四款游戏的具体美术、图标、字体、边框或构图资产。

## 2. 必须查证的内容

- 每款游戏分别记录：
  - 生命与关键生存信息的位置、常驻程度和优先级；
  - 能量/资源/货币等信息的位置与显隐策略；
  - 普攻、技能、道具或冷却槽的数量、分组与按键对应；
  - Buff、Debuff、层数、临时状态如何压缩展示；
  - 三选一或类似奖励选择如何组织标题、稀有度、说明、对比与确认；
  - 哪些信息常驻，哪些信息按需出现，哪些依靠世界内反馈而非 HUD。
- 使用可核验的网页、官方视频/截图、商店页或可靠资料；最终文档附直接链接、访问日期，并区分“来源事实”和“设计推断”。
- 不得凭记忆捏造不存在的 UI；无法确认时明确标注未知。

## 3. 当前界面审计

以 `docs/agent_tasks/evidence/task12/01_combat_hud_1152x648.png` 和任务 12 已验收实现为基准，量化：

- 常驻 HUD 大致占屏比例、遮挡区域和视觉重心；
- 重复表达、低频信息常驻、过度文字化和面板化问题；
- 玩家在战斗中必须瞬时读取的信息与可延后信息；
- 当前固定 ACTIVE_1～3 + PASSIVE_1、CurrentElement、生命、能量、目标元素层数、状态反馈中，哪些必须常驻、可折叠、可情境化。

冻结规则不能改变：共享 ACTIVE_1～3 + PASSIVE_1、CurrentElement、最多四槽、单一最终伤害数字、色觉辅助和减少动态。

## 4. 三套原创方案

每套必须同时给出：

- 1152×648 战斗 HUD 线框图，标明像素级区域、对齐、间距和最大占屏范围；
- 生命、能量、CurrentElement、三个 ACTIVE、一个 PASSIVE、冷却/忙碌/不可释放、目标元素层数和短时反馈的摆放与显隐规则；
- 三选一奖励界面线框图，明确三张奖励卡的比较顺序、名称/类型/策略/效果说明、稀有度或类别、确认/返回路径；
- 信息优先级、扫视路径、遮挡成本、可访问性、900×540 退化策略；
- 与当前方案相比减少了哪些常驻面积与文字，同时没有牺牲哪些关键语义；
- 明确原创性说明：只借鉴信息组织原则，不复制具体游戏美术。

三套方案应有明显不同的布局逻辑，例如：

1. 角落聚合 + 底部紧凑技能带；
2. 玩家附近情境 HUD + 极简边缘常驻；
3. 左下生存簇 + 右下技能扇区/双层节奏。

示例仅用于区分方向，不限定最终方案。

## 5. 评估矩阵

用统一指标对三套方案评分并说明依据：

- 战斗扫视距离；
- 常驻占屏面积；
- 技能/冷却辨识；
- 元素和层数辨识；
- 三选一比较效率；
- 色觉辅助与减少动态兼容；
- 900×540 适配风险；
- Godot 实现复杂度。

给出推荐方案及保留一个备选，不直接进入代码实现。

  - Status `304×144`，约 `5.86%`；

- 三套方案必须分别给出目标常驻占屏率；不得通过把正文缩到 12px 以下来换取“紧凑”，应优先移除重复文本、情境化目标信息和建立渐进披露。
- 奖励选择发生在战斗暂停/安全阶段，可以使用更大的比较界面；战斗 HUD 与奖励界面不需要共享同一种面板密度。
