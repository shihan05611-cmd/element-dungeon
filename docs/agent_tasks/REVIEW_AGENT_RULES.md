# Review Agent 分级验收规则

本文件只规定 Review Agent 如何按风险执行 `L1 / L2 / L3` 验收，不负责需求拆解、任务编号、
执行派发、归档或 Git。中枢管理规则见 `CENTRAL_REVIEW_RULES.md`；只有 L3 才必须继续读取
`REVIEW_L3_PLAYBOOK.md`。

## 1. 共同边界

- Review 与执行职责分离。Review 不实现、不顺手修复、不扩大 allowlist，也不自行标记
  `ACCEPTED` 或执行 Git 写操作。
- 先读任务书、冻结交付和 diff，再按任务书标注的等级验收。未标等级时默认 `L2`，不得自行
  降为 `L1`。
- 验收关注实际风险和用户结果，不以门禁数量衡量质量。执行侧证据可以按等级复用，不要求每次
  重建发布级证据包。
- 已证明实现或合同有缺陷时输出 `FAIL`；当前等级不足以可靠判断、但尚未证明实现错误时输出
  `ESCALATE`，并说明建议升级到的等级与原因。
- Review 只输出 `PASS / FAIL / ESCALATE`。`PASS` 代表当前等级的门禁已满足，最终接受、归档和
  Git 检查点仍由中枢决定。

## 2. L1 轻量 Review

### 2.1 适用范围

适合边界清楚、影响局部、失败易发现且易回退的修改，例如：文案、常量、单一场景坐标、局部
布局、既有资源替换、测试/文档同步，以及不改变公共接口或权威状态的窄修复。

### 2.2 必做

1. 阅读任务书、执行回传和完整 diff，确认修改文件均在 allowlist 内；
2. 检查直接边界：调用点、资源引用、场景坐标或 UI 状态没有越界修改；
3. 复跑专项测试，或在执行结果确定、日志完整且改动非常窄时认可执行侧专项结果，并至少抽查
   一个关键断言、日志或实际结果；
4. UI/视觉改动查看 1～3 张最能证明结果的实际画面，重点看目标状态、裁切、遮挡和可读性；
5. 记录未覆盖风险，给出 `PASS / FAIL / ESCALATE`。

### 2.3 默认不做

- 不建冷副本或独立 profile；
- 不跑全量回归、完整 smoke 矩阵或多轮重复性测试；
- 不做全项目 SHA、完整 sidecar 清单或共享缓存零漂移审计；
- 不重新生成整套截图，也不建立独立 evidence 包。

如果完成判断必须依赖上述任一重型动作，输出 `ESCALATE`，不要把 L1 临时膨胀成 L3。

## 3. L2 标准 Review

### 3.1 适用范围

适合大多数常规玩法、UI、场景和局部事务修改：会穿过数个既有调用点，但权威边界已明确，
没有公共协议迁移、随机正确性、已知不稳定或大范围跨域影响。

### 3.2 必做

1. 阅读任务书、冻结 diff，并追踪关键调用链和权威提交点；
2. 独立复跑专项测试，以及至少一个直接依赖回归；
3. 执行一次与改动直接相关的场景 smoke；无需扩大为全游戏 smoke 矩阵；
4. 视觉、交互或手感修改必须实际运行检查一次，覆盖主要成功路径和明显失败边界；
5. 扫描本轮实际运行日志中的脚本错误、解析错误、引擎错误和崩溃；
6. 核对 allowlist 与任务外保护项没有明显越界，输出 `PASS / FAIL / ESCALATE`。

L2 默认直接使用执行者冻结的验证根或其他不会改动共享项目的现成验证环境；不要求为 Review
另建全新冷副本。若只能在共享项目运行，必须避免控制已开启的共享编辑器，不得保存、reimport
或回流生成 sidecar。

### 3.3 必须升级 L3 的信号

- 修改公共接口、存档/迁移格式、跨房持久状态、经济或 revision 原子性；
- 涉及随机分布、确定性、并发、竞态或已出现跨进程偶发失败；
- 影响多个职责域，直接依赖范围无法可靠收束；
- 性能优化需要 before/after 结论；
- 冻结 diff、执行证据和任务书互相矛盾；
- 现成验证环境无法安全复现，或共享工作区有被改写风险；
- 用户、任务书或中枢明确要求发布级/严格验收。

出现这些信号时输出 `ESCALATE`；已经复现明确缺陷时仍输出 `FAIL`。

## 4. L3 严格 Review

L3 用于高风险、跨域、随机/不稳定、性能、公共契约或发布检查点。Review 必须完整读取并遵循
`REVIEW_L3_PLAYBOOK.md`，通常包括：

- 从固定 Git 基线与精确 overlay 建立全新冷副本；
- 独立 Godot profile；
- 全量或完整影响域回归、必要的重复性验证；
- 重新生成并原尺寸检查截图；
- SHA、allowlist、sidecar 与共享工作区零漂移对账；
- 性能 before/after（仅性能任务或热路径变更）；
- 完整正式日志扫描和独立 evidence 包。

L3 仍以风险为中心：任务书没有性能或视觉目标时，不机械添加无关性能测试或截图。

## 5. 等级选择参考

| 典型风险 | 建议等级 |
| --- | --- |
| 文案、常量、单场景坐标、局部样式、资源引用修正 | L1 |
| 常规玩法/UI流程、局部权威事务、数个明确调用点 | L2 |
| 公共接口、经济/存档/跨房状态、随机分布、偶发失败、跨域改造、性能 | L3 |

文件数量只能作为辅助信号，不能单独决定等级。小 diff 也可能修改高风险权威边界；大批机械资源
变更也可能只需要 L1 或 L2。

## 6. 统一回传格式

```text
Task：<编号/名称>
Review Level：L1 / L2 / L3
Result：PASS / FAIL / ESCALATE
Reviewed Scope：<diff、调用链、场景>
Reproduced：<Review 实际重跑或实际运行>
Reused Evidence：<认可的执行侧证据；没有则写无>
Findings：<阻塞项或无>
Residual Risk：<未覆盖但可接受的风险>
Recommended Next Step：<接受、返工或升级>
```

结论应简洁、可复核。非阻塞抛光项单列记录，不因追求形式完美把 L1/L2 变成发布级验收。
