# 元素反应视觉与简短飘字

建议：`gpt-5.6-sol` / `high`

Allowlist：`CombatFeedback` 中已接受元素反应结果的世界表现分支；本任务新增的反应组合 Scene/脚本；既有 burning tick、unending trigger SpriteFrames 只读复用；与反应表现、普通伤害数字、减少动态和生命周期直接相关的自动化测试、窗口取证及 `docs/agent_tasks/evidence/task87/`。元素反应判定、层数消耗、倍率、最终伤害、被动 gameplay、Task 86 全局附着循环、技能 HUD、RunOverlay、商店和 Cloud 并行模块均不得修改；不得新增、重绘或生成人物、粒子、图标及其他位图素材。本任务必须等待 Task 86 后的中枢提交完成，未收到提交完成指令不得启动。

目标：用命中点上的双色元素组合动画和固定“反应”飘字替代机械的“反应 ×倍率 · 消耗 N 层”说明，让玩家明确知道触发了反应并直观看出火水方向与大致强弱，同时保留最终伤害数字和所有权威结算。

范围：`CombatFeedback` 对普通命中继续只生成现有最终伤害数字；反应命中生成一份更醒目的最终伤害数字和一份固定内容为“反应”的简短飘字，但不再创建包含倍率/层数的旧 `ReactionDetail`，正式 `presentation_text()` 也只能输出最终伤害与固定“反应”，不得包含 `×`、倍率、小数、消耗层数或其他机械数值。反应飘字使用现有像素字体和反应强调色，与伤害数字错开且随组合动画短暂上浮/淡出，不重复显示。精确的 `reaction_multiplier`、`reaction_consumed`、反应后伤害仍保留在 `CombatResult` 与调试 `semantic_damage_summary()`，不得删除或改值。反应视觉在权威 `hit_position` 生成，使用 `source_element_id` 推断攻击元素和被消耗的相反元素：火攻击水时先让蓝色不息 trigger 向中心收束/淡出，再让橙色 burning tick 向外爆开；水攻击火时反向组合。允许通过 AnimatedSprite2D 的 scale、rotation、modulate、z_index 和 Tween，以及无贴图的短促中心闪光实现，不得新增 PNG/SVG/序列帧。

反应强弱不显示精确数字，以 `reaction_consumed` 映射为三个有上限的表现档：1 层为弱、2 层为中、3 层及以上为强；只改变组合动画的尺寸、亮度和短促节奏，“反应”飘字本身不随层数改变文案或追加符号，不能按无上限层数生成无限实例。单次表现建议控制在 `0.45` 秒内，结束自动释放；按 cast/delivery/hit/receiver 键去重并设置合理并发上限，多目标反应各自在自身命中点呈现，不跨房或跨场景残留。目标是 Boss 时仍以命中点为中心，不按整张 Boss 立绘缩放。减少动态模式使用一帧双色叠加、静态“反应”文字与短淡出，不做位移、弹跳或旋转；普通命中、同元素减伤和未接受结果不得误生成反应组合或“反应”飘字。

需迁移断言：Task 24 等正式反馈专项中 `ReactionDetail == "反应 ×… · 消耗 …层"` 与 `presentation_text()` 第二行断言改为反应结果只有一份最终伤害 Label、一份文本严格等于“反应”且不含数字/倍率/层数的 ReactionCue，并存在唯一反应组合实例；保留“最终伤害只显示一次”、颜色、权威倍率/消耗层数和去重断言。补充火打水、水打火、弱/中/强封顶、普通命中、同元素命中、多目标、Boss 命中点、减少动态、并发上限与清场释放；不得通过删除玩法断言换取通过。

完成：真实窗口中火打水与水打火具有清楚相反的内收/外爆顺序，弱中强可感知；每次反应只出现一次“反应”飘字，没有倍率、层数或其他机械数字，最终伤害数字仍准确、唯一且可读。普通命中和同元素减伤不出现反应组合或反应飘字，快速多目标战斗无堆积、遮挡或残留，减少动态版本无位移动画。提供两种方向、三个强度、普通对照、Boss 与减少动态的同机位证据；相关专项与正式回归通过，且 Git 差异中没有新增 VFX 位图文件。
