## 3. 集成架构

### 3.1 RunSession 宿主

- 每次开始本局创建一个明确拥有者管理的 RunSession。
- 核心 RunSession 不作为全局永久单例；场景层可以使用窄 Node 宿主跨房间持有它。
- 重新开始本局必须创建全新的运行时状态，不能污染共享 Resource。

### 3.2 事件桥

把正式场景事件转换为 Agent E 的类型化 RunEvent：

- 形态切换。
- 已提交的 CombatResult。
- 敌人击杀及稳定击杀身份。
- 房间完成及稳定房间身份。

事件桥只读取提交后状态。不得让遗物、奖励或 UI 直接连接并修改 CombatReceiver、ElementCarrier 或 SkillExecutor 内部状态。

### 3.3 PlayerGrowthAdapter

负责将已提交成长快照应用到现有玩家组件：

- 攻击属性进入现有 CombatStatSnapshot 提供器，每点 +5%。
- 体质每点增加 10 最大生命。
- 能量每点增加 5 最大能量。
- 商店提交增加最大生命/能量时，当前值增加相同增量，不完全恢复。
- 应用失败必须报告并避免 UI 假显示为成功。

遗物恢复、治疗和临时属性效果通过 Agent E 的窄端口适配到 Player，不允许遗物保存 Player 引用。

## 4. UI 与流程

### 4.1 HUD

新增显示：

- 角色等级。
- 当前经验 / 下一级经验。
- 未分配属性点。
- 等级提升和存在未分配点的明确提示。

HUD 只能读取快照和提交后通知，不得计算经验或属性结果。

### 4.2 奖励与路线

- 房间结束后进入 Reward 状态并展示保存的 PendingReward。
- 技能和遗物奖励最多 3 选 1。
- 关闭重开奖励界面不得刷新选项。
- 领取成功后才允许进入路线选择。
- 技能池耗尽时路线 UI 不显示技能奖励路线。
- 新技能领取后可以立即请求装备，但装备失败不能撤销已经领取的技能。

### 4.3 商店

- 商店没有货币和购买出售。
- 显示已拥有技能、遗物、属性点和水火槽位。
- 所有操作先修改 ShopDraft。
- 取消恢复进入商店时状态；确认整体提交。
- 确认成功后属性分配不可撤销，并同步真实 Player 数值与 HUD。

### 4.4 原型流程

- 第一战结束固定技能三选一。
- 第 2、3 战前提供技能/遗物路线选择。
- 第 3 战后进入商店。
- 第 4～6 战重复流程。
- 第 6 战后进入商店并允许结束本轮原型。

首个检查点允许复用当前普通战斗房间模板，通过房间实例 ID 和 reward_type 区分进度；不得复制战斗结算逻辑。
