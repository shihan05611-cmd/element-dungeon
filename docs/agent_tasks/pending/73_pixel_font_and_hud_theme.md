## 0. 阅读方式

本任务解决的是一句话可以概括的问题：**HUD 用矢量字体和圆角矩形，游戏用像素画，两种边缘放在同一屏，UI 会被看成「不是游戏的一部分」**。

它不改布局（那是任务 72），不画位图面板皮肤（那是 P1 另案）。只做三件事：换字体、归一字号、把散落的样式代码收进 Theme 资源。

## 1. 背景事实（已验证）

### 1.1 项目没有任何字体资源

全仓库 `find` 无 `.ttf` / `.otf` / `.fnt`，也无 `.theme` 资源。所有文字走 Godot 默认矢量字体，带灰度抗锯齿边缘；而全部 sprite 是硬边无抗锯齿的像素画。

### 1.2 字号散乱且无阶梯

`scripts/combat_hud.gd` 经 `_make_label(name, text, font_size, color)`（无默认值，每处显式传入）产生的字号包括 **11 / 12 / 13 / 14 / 16 / 18**，房间标题另有 **18 / 19**（任务 72 后已并入 HUD）。这 6–7 个档位之间没有比例关系，靠 1px 之差区分层级 —— 换成点阵字体后这类差别会完全消失。

### 1.3 样式全靠运行时代码覆写，没有 Theme

`scripts/ui/combat_ui_tokens.gd` 用静态方法产出 `StyleBoxFlat`，`combat_hud.gd` 里遍布 `add_theme_stylebox_override` / `add_theme_font_size_override` / `add_theme_color_override`。后果：

1. 8 个顶层面板全部是「圆角矩形 + 1–2px 纯色描边 + 阴影」同一种形态，只靠颜色区分，没有材质层级；
2. `panel()` 默认 `radius = 8`、`flat_panel()` 默认 `radius = 6` —— 平滑圆角是矢量 UI 语汇，与像素画冲突；
3. 改一处样式要翻遍构建代码，无法整体替换皮肤。

### 1.4 任务 72 留下的回归门禁

`combat/tests/run_task72_hud_layout_tests.gd` 断言了面板矩形不重叠与安全边距。**换字体会改变文本度量**，若某个面板是随内容伸缩的，其矩形会变化 —— 该测试因此正好是本任务的溢出探测器，必须继续通过。

## 2. 改动需求

### F1 — 接入像素字体

1. 字体文件放 `assets/ui/fonts/`，许可文件（LICENSE / OFL.txt）一并入库；
2. 导入设置必须关闭全部平滑：`antialiasing = None`、`subpixel_positioning = Disabled`、`hinting = None`、`multichannel_signed_distance_field = false`；
3. 字体的 `.import` 文件入库，确保干净 clone 后设置一致。

**判据**：任意 HUD 文字在 1152×648 原生分辨率下 10 倍放大后，字形边缘无灰度过渡像素。

### F2 — 字号归一到字体原生阶梯

把 §1.2 的 6–7 个散值归并到所选字体的 12px 原生档位及其整数倍。语义仍保留四级，但不强求四个不同字号：

| 语义级 | 用途 | Fusion Pixel 12px 方案 |
| --- | --- | --- |
| 角标 | 键位号、Lv、SP、冷却数字 | 12 |
| 正文 | 槽位名、状态数值、辅助说明 | 12 |
| 强调 | Boss 名、当前元素、反馈横幅 | 12（通过颜色、容器和留白强化） |
| 标题 | 房间标题 | 24（= 12 × 2） |

字号必须以**常量**定义在 `combat_ui_tokens.gd`（如 `FONT_CAPTION / FONT_BODY / FONT_EMPHASIS / FONT_TITLE`），`_make_label` 的调用点一律引用常量，**不得再出现字面量字号**。

> **任务 74 之后的实际存量**：被动槽已无任何文字；主动槽只剩键位号与 `SP N`；技能等级改为 hover 展示（仍需字号，但不常驻）。因此本表的「正文」级主要服务于房间标题以外的 HUD 说明文字与 HP/SP 数值，**归并前先实测当前存量，不要照搬本表预设的用途清单**。

归并时若某处的层级判断有歧义（例如现在的 13 该归 12 还是 16），按「该文字是否需要在战斗中被瞬间读到」决定：是→强调，否→正文。

### F3 — 建立 Theme 资源

1. 新建 `resources/ui/combat_hud.theme`；
2. 把 §1.3 的面板样式改为 Theme 类型变体（至少三种：常规面板 / 强调面板 / Boss 面板），构建代码改用 `add_theme_type_variation`；
3. `combat_ui_tokens.gd` 的**颜色 token 值保持不变**，本任务只改这些颜色的组织方式，不做配色调整（配色重取属 P1 另案）。

允许保留少量运行时覆写用于**动态状态**（冷却遮罩、受击闪烁、槽位瞬时反馈等随游戏状态变化的部分）。判据是：**静态外观**必须来自 Theme，只有随状态变化的才允许留在代码里。

### F4 — 面板材质像素化

在不引入位图资源的前提下（9-slice 位图皮肤属 P1 另案），调整 `StyleBoxFlat`：

1. 圆角改为 **0**（直角）或 **2px**，不得保留 6 / 8 的平滑圆角；
2. 描边宽度取整数像素，不随分辨率缩放产生半像素；
3. 可加一条内侧 1px 亮边模拟像素风斜面浮雕；
4. `shadow_size` 若保留，须为整数且不产生渐变羽化边。
