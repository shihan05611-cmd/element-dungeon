# 中枢协作规则（极简版）

本文件是项目当前唯一的中枢管理入口。历史规则已隔离到 `docs/_discarded/agent_rules_legacy_20260820/`，不再生效。

## 1. 中枢只做必要协调

- 理解用户目标；只有工作需要委派、跨步骤跟踪或独立 Review 时才建立任务书。
- 做最小必要拆分，选择合适的执行者与 Review Agent，处理依赖、阻塞和修改范围冲突。
- 主动收取结果，不让用户搬运消息。
- 不替执行者实现，也不替 Review Agent 重复验收。

用户当前明确决定优先于旧文档；当前仓库事实优先于历史记录和聊天记忆。关键事实缺失且会改变结果时才询问用户。

## 2. 任务书只保留三项

```markdown
# <任务名>

目标：<期望结果>
范围：<允许改什么；无特殊边界时一句话即可>
完成：<可判断的完成条件>
```

只有在省略会导致误做时，才追加关键依赖、禁止项或背景。除此之外均为可选：不强制编号、复杂状态表、固定章节、Review 等级、模型/线程字段、逐文件 allowlist、历史考古、方案推导、测试矩阵、证据目录或固定回执。

旧任务书无需返工；执行和 Review 只提取其中与当前目标、范围和完成条件直接相关的内容。

## 3. 执行者

- 在约定范围内完成工作，不顺手扩大需求，不覆盖来源不明或其他任务的改动。
- 运行对当前改动最相关、足以发现主要错误的检查。
- 交付只需说明：做了什么、怎样验证、是否有风险或阻塞。格式自由。

## 4. Review 是最终验收

- Review 独立查看任务目标、实际 diff/产物和执行结果，并做足以判断正确性的最小验证。
- 视觉改动查看实际画面；行为改动运行直接相关测试；只有公共契约、跨域或明显高风险改动才按需要扩大验证。
- 默认不要求 冷副本、独立 profile、全量回归、全库 SHA、截图矩阵或 evidence 包。
- Review 输出 `PASS`、`FAIL`，或确有外部条件缺失时输出 `BLOCKED`，并附简短理由。
- **Review 的 `PASS` 立即等同最终接受。** Review 可直接把任务标为 `DONE` 并移入 `completed/`；中枢信任结论，不再复跑门禁，也不再做一次 `ACCEPTED` 决定。
- `FAIL` 返回执行者修复；中枢只负责转交问题和继续跟踪。`BLOCKED` 由中枢补条件或请求用户决定。

## 5. 状态与安全

如需状态，只使用 `TODO / DOING / REVIEW / DONE / BLOCKED`。Review `PASS` 后直接进入 `DONE`。

- 工作区已有改动默认属于用户或其他任务，必须保留。
- 修改范围重叠时先协调，不互相覆盖。
- 未经用户明确授权，不做破坏性恢复、push、发布或部署。
- 上下文不可靠时重新读取任务书和仓库事实，不依赖旧摘要猜测。
