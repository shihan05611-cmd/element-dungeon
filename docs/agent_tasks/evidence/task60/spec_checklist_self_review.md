1. **在目标逻辑尺寸下可识别** — Boss 200×200、弹体 32×16、命中特效 24×24/帧、感叹号 32×32，均在原尺寸截图（见 `03_boss_native1x_and_2x_nearest_qa.png`、`07_projectile_telegraph_native_and_2x_qa.png`）核实轮廓可辨识。通过。
2. **使用整数缩放** — 主纹理裁切采用源坐标固定窗口 → 整数 `4×` 最近邻放大（Boss），弹体/感叹号在 4× 超采样画布上绘制后整数降采样（`Image.NEAREST`），最终交付文件即逻辑尺寸原图，未做非整数缩放。通过。
3. **像素颗粒与主角/普通敌人接近** — Boss 主体像素簇尺度经 `10_scale_comparison_*.png` 核对，与 cat(2×)/orc(3×)/tidal_sentry(3×) 同屏比较，颗粒不细于参照。通过。
4. **主面、暗面、高光不超过约三层** — 各形态调色板固定为 outline/dark/main/highlight 四色（含描边），主体材质三档（暗/主/高光）保持不变，仅重映射色值，未新增分层。通过。
5. **只有一个主要高光区域** — 高光色（`*_HI` 系列）仅出现在原图既有的小簇像素范围内，未扩大面积；ember 裂纹新增像素使用独立的暖色标记而非扩大高光面，占比控制在个位数像素级（远低于可见面积 10%）。通过。
6. **左上光源方向一致** — 三形态共用同一源精灵变形结果，仅重映射调色板，未改变明暗几何分布，光源方向与源图一致（源图整体呈左上主面偏亮、右下偏暗）。通过。
7. **有明确接地点** — 三形态与 hurt/death 均由 `add_contact_shadow` 生成统一的短硬边接触阴影（sha 见 `stats_consolidated.json`），阴影固定在共享基线 y=170。通过。
8. **轮廓在暗色、水色、火色、紫色背景上均可读** — 见 `04_boss_4background_readability.png`（三形态）、`06_projectile_4background_readability.png`（四弹体）、`08_telegraph_4background_readability.png`（感叹号，单独验证）。通过；plain 形态在 fire 背景下对比度偏低但描边仍提供可辨边界，属于可接受范围。
9. **交互状态不依赖文字也能区分** — hurt 沿用源图的高亮红色痛觉像素簇，death 使用收缩坍塌姿态（源 death f2，bbox 高度显著低于 idle），二者与三种存活形态在剪影层面即可区分，不依赖文字。通过。

11. **无非整数缩放造成的新颗粒** — 全流程仅使用 `Image.NEAREST` 整数倍缩放与逐像素程序化编辑，未使用任何插值/双线性缩放。通过。
12. **无文字、水印、背景污染或多余阴影** — 全部正式 PNG 背景为透明（RGBA，alpha=0），未嵌入文字/水印；仅有的阴影是 §4.3 要求的接触阴影，未见散射投影。通过（QA 合成图上叠加的文字标签仅存在于证据文件中，不在正式交付 PNG 内）。
