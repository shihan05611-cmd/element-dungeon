# 《元素地牢》局内构筑与成长机制变更需求

> 文档性质：产品需求基线 / 后续实现任务的拆分依据  
> 状态：已完成需求收束；Task42 普通宝箱与当前经济节奏已定稿
> 形成日期：2026-08-05  
> 依赖基线：任务 25 已验收的商店技能即时装配；《元素地牢》关卡流程竞品探测与适配设计报告  
> 本文边界：只记录需求，不修改代码、场景、资源、UI 或数值配置

## 1. 目的

本需求收束最近几轮关于主动技能、被动技能、SP、遗物、梦之尘、技能升级、角色等级和属性点的讨论，作为后续架构设计、任务拆分、实现和验收的统一口径。

本轮希望把局内成长集中为一条易理解的主线：

```text
战斗与风险选择
→ 获得梦之尘
→ 购买主动/被动技能，或强化已有主动技能
→ 调整 3 个主动槽与 4 个被动槽
→ 在后续战斗中验证构筑
```

角色等级、经验、属性点与遗物仍可作为未来扩展能力保留在项目中，但不参与当前正式局内循环。

## 2. 最终决策摘要

| 议题 | 本轮决定 | 当前要求 |
| --- | --- | --- |
| 主动技能释放约束 | 保留 SP 主导，不改为通用冷却制 | 维持现有释放规则；不新增全局轮转冷却，不强制阻止单技能专精 |
| 主动技能槽 | 保留 3 个 | `ACTIVE_1～3` 只承载主动技能 |
| 被动技能槽 | 扩展为独立 4 个 | `PASSIVE_1～4` 只承载被动技能，与主动技能分区展示和管理 |
| 遗物 | 暂不启用 | 不生成、不奖励、不展示、不结算；保留代码和资源以备未来恢复 |
| 局内通用货币 | 只使用梦之尘 | 不再引入金币；购买技能和强化主动技能使用同一余额 |
| 主动技能成长 | 启用局内技能等级 | 主要提供数值提升；每个主动技能独立记录等级和累计强化投入 |
| 被动技能成长 | 首版不升级 | 购买、拥有、装配即可；不使用等级、品质或强化分支 |
| 角色等级/经验 | 保留系统但关闭 | 新局固定中性状态，不获得经验，不显示等级或经验 UI |
| 属性点/商店加点 | 保留系统但关闭 | 当前商店不提供属性分配，属性投影保持中性值 |
| 换装 | 保留即时生效 | 普通换槽不退款、不重置技能等级；已拥有技能离槽后仍保留其等级 |
| 强化返还 | 启用可控返还 | 购买成本不返还；主动技能强化投入默认返还 70%，同时重置该技能至基础等级 |

## 3. 核心设计原则

### 3.1 局内只保留一条常规数值成长主轴

当前正式局内数值成长以“梦之尘强化主动技能”为主。角色属性点、遗物品质、多乘区随机词条等系统不同时启用，避免玩家必须并行理解多套增长曲线，也避免敌人强度被迫同时抵消多条数值膨胀。

被动技能仍可提供条件、机制或构筑方向，但首版不形成第二套需要持续喂资源的等级经济。

### 3.2 允许玩家自行决定技能使用集中度

本项目不因担心“最终只使用一个主力技能”而强制切换为冷却轮转。玩家可以选择：

- 集中梦之尘强化一个主力技能；
- 均衡强化多个技能以覆盖不同战况；
- 把资源用于购买更多主动或被动选项，而非继续强化。

内容平衡可以通过敌群结构、技能适用场景、SP 生成与消耗、站位风险等方式提供多技能价值，但本需求不加入硬性的轮流释放、强制换招或全局冷却规则。

### 3.3 单货币承担机会成本，不再增加金币层

梦之尘同时用于购买和强化，使每次消费自然形成选择：

- 立刻买新技能，扩大构筑宽度；
- 强化现有技能，提高当前战力；
- 暂时储蓄，等待后续更合适的商店候选。

后期更换构筑的主要成本来自已经投入旧技能的强化资源，而不是额外设置一套金币获取和价格膨胀。技能购买价因此不需要随流程剧烈上涨。

## 4. 配装结构需求

### 4.1 槽位模型

正式配装从当前“3 个 ACTIVE + 1 个 PASSIVE，且 ACTIVE 可装被动”调整为：

```text
主动区：ACTIVE_1 / ACTIVE_2 / ACTIVE_3
被动区：PASSIVE_1 / PASSIVE_2 / PASSIVE_3 / PASSIVE_4
```

规则如下：

1. `ACTIVE_1～3` 只允许主动技能；被动技能放入时必须明确拒绝且不产生部分状态。
2. `PASSIVE_1～4` 只允许被动技能；主动技能放入时必须明确拒绝且不产生部分状态。
3. 最多同时装备 3 个主动技能与 4 个被动技能，允许主动槽或被动槽留空。
4. 是否允许 0 个主动技能由后续新手保护规则决定；Runtime 数据结构不应通过混放被动来表达这一状态。
5. 同一技能默认不能同时占据多个槽位。
6. 四个已装备被动效果分别只注册一次；换槽不得造成重复注册、残留效果或重复触发。

这是一项有意改变既有 `ACTIVE 可放 PASSIVE` 契约的需求。后续实现必须同步更新对应契约、迁移、测试、HUD 和商店，不能为了保留旧测试而继续暴露混装规则。

### 4.2 展示层级

主动技能和被动技能不得继续作为同一条等权技能带中的四个同类格子展示。

- 主动区是操作层：突出按键、SP 成本、是否可释放和必要的施放状态。
- 被动区是构筑层：使用四个独立的小型常驻图标或独立面板，不显示释放键、SP 消耗或虚假冷却。
- 商店/配装页分别提供“主动技能”和“被动技能”区域、筛选或页签，不能依靠一个混合列表让玩家自行辨认。
- 被动触发可提供短暂描边、计数或世界表现，但不得与主动技能可释放状态混淆。

具体版式另立 UI 任务设计，本需求只冻结信息架构。

## 5. 主动技能与 SP 需求

### 5.1 保留 SP 主导的释放模型

1. 主动技能继续以 SP 是否足够作为主要资源约束。
2. 不把所有主动技能改为主流 Roguelite 常见的统一冷却轮转。
3. 现有前摇、后摇、动作忙碌、重复提交保护或极短技术性再触发保护可以保留；这些不应被扩展成主导构筑的长冷却系统。
4. 本轮不新增“同一技能连续使用惩罚”“必须轮换技能”“共享全局冷却”等硬性反专精机制。
5. SP 扣除、释放接受、失败回滚与现有权威事务边界保持不变。

### 5.2 技能升级范围

主动技能购买后处于基础等级 `Lv.1`。后续可消耗梦之尘逐级强化。

首版升级只改变明确声明的效果数值，例如伤害、治疗量、护盾量或同类效果强度。除非某个技能另有独立设计，不得让通用等级系统自动改变：

- 技能行为形态、弹道或作用对象；
- 元素附着/反应的全局结算公式；
- SP 成本；
- 主动槽数量；
- 冷却规则；
- 品质、随机词条或分支进化。

每个技能必须由数据声明基础效果、各级数值或成长公式、最高等级和各级价格，不能把所有技能强行套入同一伤害倍率。

## 6. 梦之尘经济需求

### 6.1 唯一钱包

每局只有一个梦之尘余额。当前正式循环不增加金币、银币、商店券等第二种常规购买货币。

梦之尘至少可用于：

- 购买未拥有的主动技能；
- 购买未拥有的被动技能；
- 强化已拥有的主动技能；
- 重置主动技能强化投资时接收返还。

首版不用于被动升级、遗物购买、角色属性加点或局外永久成长。

### 6.2 获取来源

梦之尘应拥有独立的奖励字段和结算口径，可来自普通战斗、房间完成、精英、风险条件或特殊节点。

不得直接把现有经验值字段改名后原值照搬。原经验曲线服务于逐级阈值，梦之尘服务于消费经济，两者需要独立调参。击杀、房间完成等事件仍可继续发出供去重、被动效果、战绩和其他系统消费，但在成长关闭模式下不提交经验。

### 6.3 价格结构

- 主动/被动技能的基础购买价应相对平滑，可因稀有度、强度或候选质量有有限差异，但不按房间进度剧烈指数膨胀。
- 主动技能升级价格随等级递增，使深度专精自然产生更高边际成本。
- 购买价格、升级价格、最高等级和返还比例必须数据驱动，便于平衡迭代。
- 商店显示购买或升级后余额，并明确区分“购买新能力”和“强化已有能力”。

精确产出、价格表和最高等级不在本需求中冻结，需通过独立数值表和模拟验证。

### 6.4 购买、强化与返还事务

所有梦之尘操作必须由局内权威状态执行原子事务：

1. 余额不足、候选失效、技能已拥有、等级已满或阶段非法时，余额、拥有库、技能等级、累计投入和配装全部不变。
2. 购买成功时一次性扣除购买价并加入拥有库；基础购买价不计入可返还强化投入。
3. 强化成功时一次性扣除本级价格，技能升一级，并把实际支付额计入该技能的累计强化投入。
4. 普通装备、卸下、主动槽互换或暂时不装备，不触发退款，也不重置技能等级。
5. 已拥有技能的独立等级在离槽后保留，重新装备时恢复原等级。
6. 玩家主动执行“重置强化投资”时，该主动技能回到 `Lv.1`，累计强化投入清零，并返还 `floor(累计强化实付 × 70%)` 的梦之尘。
7. 购买价永不返还；同一次投入不能重复返还，事务重放不得凭空生成梦之尘。
8. 返还比例首版默认 70%，实现为可配置数据；若后续测试在 60%～75% 区间调整，不应引发架构修改。

本文把讨论中的“换技能返还”规范化为“重置旧技能的强化投资”。这样可以同时满足“换装后技能等级仍保留”和“需要时可回收部分沉没强化成本”，且不会出现反复卸下、退款、再装备的资源漏洞。

### 6.5 消费入口

首版默认只在商店或明确的安全整备节点购买、强化和重置，战斗中不能打开完整成长操作。这样可复用现有商店阶段与即时装配事务，也能为消费决策提供稳定节奏点。

技能装配、换槽和卸下继续即时生效；购买与强化也应在玩家明确确认单笔消费后立即提交。离店按钮只负责离开或继续前进，不再显示“确认属性并离开”。

## 7. 角色等级与属性成长的关闭需求

### 7.1 保留但不启用

角色等级、经验、属性点和商店属性分配不删除，作为未来可重新评估的独立模块保留。当前新局使用关闭模式：

- 角色等级保持 `1`；
- 当前经验保持 `0`；
- 未分配属性点保持 `0`；
- 各项已分配属性保持 `0`；
- 不从击杀、房间完成、遗物或其他来源提交经验；
- HUD、奖励页、商店和结算页不展示等级、经验条、未分配点提示或属性分配控件；
- 商店草稿不创建可提交的属性变化；
- 玩家基础生命、攻击、SP/能量等不因关闭的 ProgressionState 获得额外倍率。

### 7.2 隔离方式

后续实现应使用局内规则或功能模式关闭该系统，而不是删除领域对象或散落大量临时判断。建议至少支持：

- `DISABLED`：当前正式模式，中性快照且不接收经验；
- `OBSERVE_ONLY`：可选开发模式，仅记录理论经验，不投影战斗属性；
- `ENABLED`：未来恢复旧等级/属性玩法时使用。

模式在一局开始时冻结，当前不要求中途切换。

`PlayerGrowthAdapter` 或等价的玩家数值合成层不能随角色成长一起删除或整体停用，因为被动技能、临时效果、治疗和未来其他来源仍可能依赖它。关闭的只是“角色等级/属性点来源”，不是整个战斗属性投影能力。

## 8. 遗物关闭需求

遗物系统暂时不参与正式局内玩法：

- 新局不生成或授予遗物；
- 路线和奖励候选不出现遗物房、遗物奖励或遗物商店项；
- HUD、背包、商店和结算不展示遗物区域；
- 遗物 Runtime 不注册新效果，不参与梦之尘、经验或战斗结算；
- 当前遗物代码、契约、资源和测试资产保留，不执行破坏性删除；
- 未来重新启用必须通过统一功能规则恢复，不能要求从 Git 历史找回系统。

被动技能不是遗物的 UI 换名。四被动属于受槽位上限约束的配装内容；遗物仍是独立、当前关闭的系统。

## 9. 奖励、路线与关卡流程调整

此前关卡报告中的“技能奖励 / 遗物奖励 / 经验与属性点”不再是当前正式奖励结构。后续流程应调整为：

```text
战斗房（战 1～5：首波 3～5 + 一轮休眠援军 2～3）
→ 两波清场后显示实体普通宝箱
→ 按 F 开箱：稳定 50% 未拥有 reward_pool 技能 / 50% 150 梦尘
→ 开箱后解锁实体传送门，按 F 推进
→ 查看下一房的风险、敌群和资源倾向
→ 战斗或特殊节点
→ 战 3 后唯一实体商店购买、强化、重置和即时配装；从出口门离开
→ 后续战斗验证构筑
→ 最终首领清场后开启零奖励结算宝箱进入结果
```

要求如下：

1. 常规房间不再显示旧奖励三选一页面；战 1～5 的实体宝箱可一次发放未拥有的正式 `reward_pool` 技能，或 150 梦尘，技能仍可在商店购买。
2. 遗物路线在遗物关闭期间移除，不能用无效占位候选填充。
3. 路线选择继续明示遭遇强度、敌群特征、额外条件与梦之尘/商店机会，避免退化为只比较数值大小。
4. 一局只在战 3 后进入一个实体商店；UI 不提供绕过出口门的离店按钮。
5. 最终首领的击杀、完成与结算宝箱奖励均为 0；开启结算宝箱直接进入战绩结算。
6. 关卡采用的“固定层级骨架 + 房间级透明分支 + 策划模板随机组合”方向不因本需求改变，只替换其成长与奖励内容。

普通宝箱是当前唯一常规免费技能入口；特殊事件仍须另立合同，不作为本轮范围。

Task42 最终冻结补充：奖励类型读取稳定 `run_id + room_id` 哈希最低位，技能分支使用移除该位后的稳定值对排序后的未拥有候选取模；这保持确定性与 50/50 类型分支，同时消除四候选时只能覆盖部分索引的偏差。技能池为空仍固定为 `150` 梦尘。safe/risk 五个普通战基础总收入为 `595 / 700`，到唯一商店前为 `345 / 365`。

固定验证局 `task31_safe` 的宝箱为 `300` 梦尘及 `elemental_laser → elemental_fury → element_reclaim`，最终收入/购买/升级/返还/余额为 `895 / 300 / 300 / 105 / 400`；`task31_risk` 为 `450` 梦尘及 `elemental_laser → elemental_fury`，对应 `1150 / 390 / 115 / 0 / 645`。这些数字冻结当前求职原型节奏，不宣称敌人伤害/生命、房间美术、长期 meta 或完整商业平衡已经完成。

## 10. UI 与信息需求

### 10.1 战斗 HUD

- 保留生命、SP/能量、当前元素与三个主动技能的战斗信息。
- 主动技能显示按键、SP 成本、是否可释放和必要短状态；不新增通用长冷却轮转表现。
- 四个被动技能使用独立区域和更低视觉权重；触发反馈不得挤占主动技能操作区。
- 隐藏角色等级、经验条、属性点提示和遗物区。
- 梦之尘余额不必在持续战斗中占据高权重，可在拾取反馈、路线、商店和暂停详情中清晰显示。

### 10.2 商店/整备

商店至少支持：

- 查看梦之尘余额；
- 购买主动技能；
- 购买被动技能；
- 查看主动技能当前等级、下一级提升和价格；
- 强化主动技能；
- 查看累计强化投入、预计返还和重置后等级；
- 分区装配 3 主动 + 4 被动，且装配即时生效；
- 清楚提示余额不足、满级、已拥有、类型不匹配和候选失效等失败原因；
- 以“离开商店”“继续前进”等准确文案结束整备，不再出现属性确认语义。

所有界面只显示权威快照或由权威事务返回的结果，不能在 UI 内自行扣款、升级或计算最终返还。

## 11. 数据与权威状态要求

后续实现至少需要表达以下局内事实，具体类名由架构任务决定：

- 当前梦之尘余额与 revision；
- 每个已拥有技能的购买状态；
- 每个主动技能的当前等级；
- 每个主动技能的累计强化实付；
- 主动/被动分区的七槽权威映射；
- 角色成长模式与遗物启用状态；
- 购买、强化、重置的结构化成功或失败结果。

`RunSession` 或等价局内聚合根继续作为消费、拥有、升级和配装的唯一权威协调者。余额、等级、累计投入、拥有库和配装之间的跨对象修改必须原子提交，并遵守 revision、陈旧请求和重复事件保护。

存档/读档、断线恢复或跨局永久技能等级不属于当前范围；上述状态均按单局数据设计。

## 12. 验收场景

后续实现任务最终至少需要覆盖以下产品场景：

1. 新局只有一个梦之尘余额，无金币、经验增长、属性点或遗物候选。
2. 购买主动技能成功后只扣一次梦之尘，技能以 `Lv.1` 加入拥有库；余额不足时全状态不变。
3. 购买被动技能成功后可装入任一被动槽，但不能升级。
4. 三个主动槽拒绝被动，四个被动槽拒绝主动；失败无部分换装。
5. 四个不同被动同时装备时分别恰好注册一次，换槽、卸下和重新装备不重触发旧实例。
6. 主动技能仍按现有 SP 权威事务释放，没有因本需求新增全局冷却或强制轮换。
7. 强化主动技能扣除正确价格、提升一级并记录实际投入；满级或余额不足时全状态不变。
8. 技能卸下、换槽再装回后等级与累计投入保持不变，普通换装不退款。
9. 重置 `Lv.N` 主动技能时只返还累计强化实付的 70% 向下取整，购买价不返还，技能回到 `Lv.1`，重复提交不重复退款。
10. 角色成长关闭时等级 1、经验 0、属性 0；击杀和房间事件仍可被其他系统消费，但不产生经验或属性投影。
11. 关闭角色成长后，被动技能和合法临时效果仍能通过数值合成层正确生效。
12. 遗物关闭时目录中即使保留遗物资源，正式路线、奖励、商店、HUD 和 Runtime 也不出现遗物。
13. 商店购买、强化和即时装配后的 UI 与同一权威快照一致；离店不再提交属性草稿。
14. 最终首领清场后显示零奖励结算宝箱；按 F 开启后进入结算，不产生无验证窗口的梦尘或局内技能成长奖励。

除领域测试外，还需覆盖实际 1920×1080 与 2560×1440 UI、主场景 smoke、商店真实交互、四被动同时装备，以及旧成长/遗物关闭但代码仍可加载的回归门禁。

## 13. 非目标

本轮不包含：

- 把主动技能切换为统一冷却制；
- 为防止单技能专精而加入强制轮换；
- 被动技能升级、品质、随机词条或合成；
- 遗物重做或重新启用；
- 删除角色等级、经验、属性点或遗物代码；
- 局外永久成长、长期存档或跨局货币；
- 技能行为分支、进化树或类似《梦之形》精华插槽的完整修饰系统；
- 精确梦之尘掉落、商店刷新、价格曲线和敌人数值表；
- 本需求文档阶段的任何项目代码、场景、资源或 UI 修改。

## 14. 平衡风险与观测指标

### 14.1 单技能专精是否成为唯一解

单技能主力本身不是失败；只有当不同房型、敌人和资源状态下，其他两个主动槽长期没有实际价值时才需要干预。首轮测试至少记录：

- 各主动技能的释放占比和 SP 消耗占比；
- 梦之尘在购买、主力强化和副技能强化之间的分布；
- 玩家携带但整层未使用的主动技能数量；
- 单技能专精与多技能构筑的通关率、受伤量和房间时长。

优先通过敌人职责、攻击窗口、距离和元素需求制造技能分工；只有数据证明 SP 模型无法形成选择时，再单独评估资源规则，而不是预先改成冷却制。

### 14.2 生存成长不足

若主动技能升级主要提升输出，敌人伤害成长不能继续假设玩家会从属性点获得生命和防御。首版需控制敌方伤害曲线，并通过被动、恢复、护盾、走位空间或受控补给提供生存选择。

### 14.3 单货币挤压购买乐趣

若最优解始终是“不买新技能、只强化初始技能”，应优先检查：

- 早期技能购买价是否过高；
- 初始技能强化曲线是否过强；
- 商店候选是否与当前构筑无关；
- 房间是否缺少需要新工具解决的差异；
- 返还率是否让试错成本仍然过高。

不应第一时间再增加金币来掩盖上述问题。

## 15. 建议的后续任务拆分

本文是跨系统主需求，不应由单个实现任务一次性修改全部项目。建议按依赖顺序拆分：

1. **规则与迁移设计**：冻结 3 主动 + 4 被动契约、旧四槽快照迁移、成长/遗物功能模式和梦之尘领域模型。
2. **梦之尘与技能等级领域**：实现余额、购买、主动技能升级、累计投入、70% 重置和原子事务，不先接 UI。
3. **七槽配装与被动 Runtime**：实现分区槽位、四被动注册和现有商店即时装配迁移。
4. **奖励与关卡接线**：把经验、免费技能/遗物路线迁移为梦之尘与购买机会，修正最终首领结算。
5. **HUD 与商店 UI**：重排主动/被动展示，接入购买、强化、返还和关闭态信息。
6. **内容与数值验证**：为主动技能补等级数据，建立梦之尘产销表、敌人曲线和多构筑实测。
7. **独立回归验收**：覆盖领域事务、真实 RunSession、实际 Viewport、旧系统关闭态与全量门禁。

每个任务必须单独列出文件 allowlist、禁止范围、迁移策略和验收证据；不得直接用本文作为无限制修改整个项目的授权。
