# 共享技能槽与元素释放规则

> 状态：方案一 P0 冻结规则。程序、策划、UI 和测试均以本文为共同依据。

## 1. 固定栏位

- 全元素共享唯一一套技能栏：主动位置 1 / 2 / 3 + 被动位置 1。
- 固定普通攻击在这四个位置之外，不参与配装。
- 元素变化永远不替换已装备内容；同一按键在所有元素状态下保持同一技能 ID。
- 主动位置允许装备主动技能或被动技能；被动位置只允许被动技能。
- 同一技能 ID 最多占用一个位置。
- “0 主动 + 4 被动”合法，可以保存并进入战斗；配装界面必须提示“当前没有可按键技能，战斗将依赖普通攻击与被动”。
- 主动位置装入被动后，该被动持续生效，但对应按键不发起释放，也不显示能量或冷却。

## 2. 技能分类

技能使用两个正交维度，禁止把它们混成一个枚举。

### 2.1 行为类型

- ACTIVE：可以由主动位置按键请求释放。
- PASSIVE：装备后注册持续效果，不能发起释放。

### 2.2 元素策略

- EXCLUSIVE_ELEMENT：绑定一个固定元素。接受释放时自动把 CurrentElement 切换到该元素，并锁定该元素。
- CURRENT_ELEMENT：不自动切换；接受释放时读取并锁定当前元素。
- NEUTRAL：不自动切换；CastSnapshot 的锁定元素为 NONE。

被动技能也必须声明元素策略，用于 UI 标识和被动条件，但元素策略不能让被动技能变成可释放技能。

## 3. CurrentElement

- 玩家只有一个权威 CurrentElement 状态。
- 当前内容只配置水、火，但控制器必须读取有序可用元素列表，不能在切换逻辑中写死水火分支。
- 手动切换按有序列表循环；未来增加第三、第四元素时不新增技能栏。
- 元素变化事件必须包含：旧元素、新元素、来源、单调递增事件序号和时间戳。
- 来源只有 MANUAL 与 SKILL_AUTO；遗物和被动可以明确选择响应全部、仅手动或仅自动来源。
- 新旧元素相同时视为成功的无变化操作，但不发布元素变化事件。
- 重复输入、同步回放或重复事件序号不能重复触发遗物和被动。

## 4. 释放事务

流程固定为：

    REQUEST → VALIDATE → ACCEPT/COMMIT → STARTUP → ACTIVE → RECOVERY → IDLE

### 4.1 接受前

必须完成技能身份、行为类型、控制状态、能量、冷却、可用元素和生成配置验证。任一失败：

- 不切换元素；
- 不扣能量；
- 不开始冷却；
- 不生成攻击；
- 只返回结构化失败原因。

### 4.2 接受提交

- 专属技能在接受事务内自动切换并锁定固定元素。
- 通用元素技能锁定提交瞬间的 CurrentElement。
- 无属性技能锁定 NONE。
- 技能 ID、元素、属性、Payload 和生成参数同时锁定。
- 元素切换、能量、冷却和 Cast 状态必须整体提交，外部监听者不能观察到半提交。
- 专属技能的目标元素已经是当前元素时不发布变化事件。

### 4.3 打断与取消

- 接受后发生的元素切换不回滚。
- 尚未进入生成点的攻击不生成；已经生成的攻击不撤销。
- 能量返还由技能静态配置决定：默认 NEVER，可配置 BEFORE_DELIVERY；冷却首版不回滚。
- 元素状态与资源返还相互独立。
- 投射物、范围、多段和延迟攻击始终使用接受时锁定的技能 ID 与元素。

## 5. 手动切换

- 手动切换不耗能、不占技能位置。
- IDLE 与 RECOVERY 允许即时切换。
- STARTUP、ACTIVE 和暂时不可操作状态只保留最后一次手动切换输入；恢复允许切换时执行一次。
- 死亡、换层和开始新局时清空缓冲输入。
- 手动切换不修改已经接受或已经生成的攻击。
- 切换成功后立即更新 CurrentElement 与所有通用技能预览。

## 6. 被动生命周期

- 每个已装备的被动技能只注册一次，与它位于主动位置还是被动位置无关。
- 卸下后必须注销；换装整体提交时不能出现新旧被动同时生效的中间状态。
- 死亡重生、换层和读档只重建一次有效注册，不得重复叠加。
- 三个主动位置同时装备三个不同被动时，每个被动分别生效一次。

## 7. 旧配置迁移

旧版按元素保存的 Loadout 只进行一次确定性迁移：

1. 先读取旧存档记录的当前元素；无效时使用配置列表第一个元素。
2. 依次读取当前元素、再读取其余元素的旧主动槽。
3. 按读取顺序去重技能 ID，取前三个放入共享主动位置 1～3。
4. 被动位置默认留空；超出三个的技能仍保留在已拥有技能库中但不装备。
5. 迁移成功后只保存新格式“slot_id → skill_id”，不得继续双写旧格式。

## 8. 战斗公式与表现

- 水火反应倍率固定为“1 + 实际消耗层数 × 30%”。
- 增伤只按实际消耗层数计算，不按来袭层数或目标原有总层数计算。
- HUD 固定显示四个位置，状态变化不能造成布局跳动。
- 元素信息必须同时使用颜色和图形；不得只靠颜色区分。
- 专属、通用元素和无属性技能分别使用固定实心、动态、空心中性标识。
- 自动切换和手动切换使用不同反馈；失败释放不得播放自动切换反馈。
- 元素切换动画约 150～200ms，仅作表现，不阻塞输入。
