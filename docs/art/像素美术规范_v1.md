# 《元素地牢 4.7》像素美术规范 v1

状态：长期美术基线

适用范围：角色、敌人、世界物件、场景背景与平台、战斗 VFX、HUD 图标和场景文字

不包含：玩法碰撞、数值、关卡逻辑与具体资产接线

## 1. 风格目标

本项目采用清晰、粗颗粒、低分辨率的横版像素美术。所有资产应满足：

- 在实际游戏尺寸下一眼识别对象类型与交互状态；
- 同屏资产使用相近的像素颗粒、比例和摄影机语言；
- 高光、阴影和材质服务于轮廓，不切碎轮廓；
- 角色、敌人、世界物件和场景属于同一个视觉世界。

现有主角与普通敌人是世界美术的尺度基准；技能图标属于 UI 层，不作为世界物件的像素密度基准。

## 2. 像素尺寸与缩放

| 类别 | 建议逻辑尺寸 | 说明 |
|---|---:|---|
| 主角动作帧 | 80×64 | 沿用现有资产基准 |
| 普通敌人动作帧 | 100×100 | 主体不应撑满画布 |
| 常规世界物件 | 约 48～100px | 以主角可见高度为比例基准 |
| HUD 小图标 | 32×32 | 必须先通过 32px 轮廓检查 |
|  |

- 世界像素资产只使用最近邻过滤。
- 禁止用高分辨率图片以非整数比例缩小来模拟像素风。
- 位置、锚点与摄影机尽量落在整数像素。
- 高分辨率生成图只能作为概念来源，正式资产须在目标逻辑尺寸下手工清理。
- 同一对象的所有状态共用画布、比例、锚点和基线。

## 3. 轮廓、透视与体积

### 3.1 识别优先级

外轮廓 → 最大色块 → 功能部件 → 材质细节 → 装饰像素。缩到目标尺寸后，若前三项仍不能让对象被识别，资产不通过。

### 3.2 横版摄影机语言

- 角色与常规世界物件采用侧视或接近正侧视。
- 普通物件最多显示一个主面和一个窄辅助面。
- 禁止明显的等距/isometric 透视。
- 门、祭坛等交互物可以略正面化，但必须与地面基线一致。

### 3.3 体积层级

- 材质默认使用暗面、主面、高光面三档；极小物件可压缩为明暗两档。
- 单个物件整体不超过 5 个主要明度层。
- 不为每个小部件单独建立高光，避免切碎主体。

## 4. 描边、光源与接地

### 4.1 描边

- 世界物件使用 1 个逻辑像素的深色外轮廓，默认不用纯黑。
- 内部结构线比外轮廓浅一级或断续处理。
- 亮色能量体可以局部破边，但不能整圈发白。

### 4.2 光源

- 默认光源来自左上，右下形成统一暗面。
- 主高光只保留一簇，通常不超过主体可见面积的 10%。
- 发光材质可有亮心，但仍需保持单一主要亮区。

### 4.3 接地

- 落地物件必须有底部压暗、硬边接触阴影或明确底座。
- 接触阴影使用低饱和暗色，不做柔软写实投影。
- 竖直物件必须有稳定接地点，禁止尖角悬空。

## 5. 色彩与材质

### 5.1 色彩

- 背景保持低明度、低饱和；角色和交互物使用中高饱和。
- 最高亮色只用于当前交互目标、攻击命中和关键能量中心。
- 同屏资产的暗部色相保持接近，避免各自使用互不相关的黑色。

### 5.2 材质

| 材质 | 主要表达 | 避免 |
|---|---|---|
| 木材 | 少量大木纹、暖主面、窄暗缝 | 独立渐变、过多细纹 |
| 金属 | 主色、窄高光、硬暗面 | 多层倒角、全边反光 |
| 石材 | 粗糙质感 | 均匀噪点、满屏裂纹 |
| 能量 | 根据对应的技能描述决定 | 多圈同亮度光带、全轮廓泛白 |
| 晶体 | 少量大切面、一个主亮面 | 细碎切面、写实玻璃反射 |

## 6. 交互物状态

可交互世界物件至少提供三个无需文字也能区分的阶段：

| 阶段 | 视觉表达 |
|---|---|
| 未解锁/锁定 | 降低饱和度和亮度，收束能量核心 |
| 可交互 | 恢复主色，点亮关键部件；可使用低幅呼吸动画 |
| 已使用 | 改变结构、姿态或核心状态，不得只用文字说明结果 |

状态切换只改变必要部件；主体不得无故漂移、缩放或变形。循环动效拆分静态结构与动态能量层，避免整件物体一起抖动。

## 7. 场景构图与文字

### 7.1 场景层级

- 背景用低对比大色块建立空间，平台与可站立边缘保持最高轮廓清晰度。
- 前景遮挡只放在边缘，不遮住角色、敌人、弹体和交互目标。
- 装饰和发光物稀疏放置，不形成均匀噪点或抢夺战斗焦点。
- 场景视觉边缘应与实际可站立边缘对齐。

### 7.2 场景文字

- 场景内的标题、提示和交互说明一律使用裸文字，不加方框、底板、卡片、胶囊、徽章或装饰边框。
- 可读性通过字体描边、轻微阴影、文字颜色、留白和摆放位置解决。
- 文字不得遮挡角色、敌人、交互物或战斗关键区域；同一信息只出现一次。

## 8. VFX 与 HUD

### 8.1 VFX 与图标

- 世界 VFX 可以比角色更亮，但颗粒尺度不能更细；单次技能只保留一个主爆点。
- UI 图标允许更高细节量，但必须在 32×32 下通过轮廓检查。
- 不得把高精度 UI 图标直接缩小后当作世界物件。
- UI 与世界像素层可以采用不同视觉语言，但层级必须清楚，不能混作同一材质。

### 8.2 HUD 信息密度

- 视觉已经表达的信息不再用文字重复；同一状态在 HUD 内只表达一次。
- 空槽、禁用、被动归属和冷却优先通过底纹、分区、灰度、遮罩或图标内数字表达。
- 固定且高频的键位不常驻提示；会随配装变化的键位必须标注。
- 战斗中只常驻需要瞬读的信息；技能说明和数值明细按需展示。
- 条形控件的数值放在条内，不额外占用一列。

## 9. 资产验收清单

每项资产提交前检查：

- [ ] 在目标逻辑尺寸下可识别，且使用整数缩放与最近邻过滤；
- [ ] 像素颗粒、比例和摄影机语言与现有角色一致；
- [ ] 轮廓清楚，明暗层级简洁，只有一个主要高光区域；
- [ ] 左上光源统一，落地物件有明确接地点；
- [ ] 在暗色、水色、火色、紫色背景上均可读；
- [ ] 交互状态不依赖文字也能区分；
- [ ] 动画各帧的画布、锚点、比例与基线一致；
- [ ] 场景文字为裸文字，无方框、底板或装饰边框；
- [ ] 无文字水印、背景污染、非整数缩放颗粒或多余阴影。
