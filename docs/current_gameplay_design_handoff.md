# 《元素地牢》当前玩法设计交接稿

> 用途：将当前项目的已实现规则同步给策划讨论或网页端对话。本文描述的是当前版本事实，不代表所有规则都已最终定案。

## 1. 当前原型目标

当前版本是横版动作战斗测试房，核心验证闭环为：

1. 玩家选择水或火形态。
2. 发射对应元素弹，使敌人获得元素附着。
3. 切换到相反形态再次命中。
4. 水火元素按层数相互消耗并触发增伤。
5. HUD 同步显示生命、能量、当前形态、技能状态和目标元素层数。

目前不是完整关卡，也未包含装备、成长、Buff、土、电、吸收或引爆等扩展系统。

## 2. 元素系统定位

元素是独立的底层战斗系统，不从属于某一个具体技能。

- 技能只负责声明攻击携带的元素及元素量。
- `ElementCarrier` 保存目标当前的水、火附着层数。
- `CombatReceiver` 统一提交伤害、元素附着和反应结果。
- 投射物和近战 Delivery 只负责命中传递，不拥有元素反应公式。
- 当前仅支持水、火；每种元素容量为 10 层。
- 同元素命中会累加，最高 10 层。
- 异元素命中会按 1:1 消耗双方元素。
- 未参与反应的来袭元素会继续附着到目标身上。

## 3. 水火反应规则

```text
消耗层数 = min(目标已有相反元素, 本次来袭元素量)
反应倍率 = 1.0 + 0.3 × 消耗层数
```

即每消耗 1 层相反元素，当前攻击增加 30% 伤害：

| 消耗层数 | 伤害倍率 |
|---:|---:|
| 0 | 1.0 |
| 1 | 1.3 |
| 2 | 1.6 |
| 3 | 1.9 |
| 10 | 4.0 |

水触发火和火触发水完全对称。

当前伤害顺序为：

```text
攻击伤害 = 技能基础伤害 × 攻击倍率 + 固定伤害加成
反应后伤害 = 攻击伤害 × 反应倍率
减伤后伤害 = max(0, 反应后伤害 - 目标固定防御)
最终伤害 = 最后统一四舍五入
```

因此反应倍率作用于防御之前。这个顺序是当前技术方案的冻结规则，但仍可作为后续策划讨论点。

## 4. 形态设计

- 玩家具有水、火两种形态。
- 两种形态拥有相互独立的技能槽映射。
- 当前两个 Loadout 暂时装配了相同技能，用于验证系统，而非代表最终内容设计。
- 通用元素技能在释放被接受时读取当前形态，并锁定为本次攻击元素。
- 投射物飞行期间切换形态，不会改变已经发出的投射物；下一次释放才使用新形态。

当前角色表现没有两套立绘：

- 水火形态共用同一套角色 Sprite 和动画。
- 水形态给角色叠加浅蓝色调，火形态叠加浅红色调。
- 切换时有约 0.2 秒的白色闪烁过渡。
- HUD、投射物颜色和战斗反馈会同步切换元素语义色。
- 当前没有角色形态专属粒子，也没有水火各自的角色动画。

## 5. 当前技能与数值

### 元素弹 `element_bolt`

- 类型：通用元素投射物。
- 当前形态决定水弹或火弹。
- 基础伤害：10。
- 元素附着：3 层。
- 能量消耗：20；玩家最大能量 100。
- 前摇：0.12 秒。
- 有效阶段：0.08 秒。
- 后摇：0.22 秒。
- 当前没有独立冷却，主要受释放状态机和能量限制。

### 近战斩击 `element_slash`

- 类型：当前为普通、无元素近战。
- 基础伤害：5。
- 元素附着：0。
- 前摇：0.08 秒。
- 有效阶段：0.12 秒。
- 后摇：0.18 秒。

### 当前操作

- `J`：近战槽。
- `Q`：主要技能槽，释放元素弹。
- `E`：切换水/火形态。

## 6. 技能系统边界

- `SkillDefinition` 保存技能的静态配置。
- `SkillLoadout` 保存不同形态的静态槽位映射。
- `SkillExecutor` 是前摇、有效阶段、后摇和取消流程的唯一时序来源。
- 能量在释放请求被接受时立即扣除；被打断不会退款。
- 释放瞬间锁定技能、形态、攻击属性和 Payload，避免飞行中被后续状态改变污染。
- 输入键位由 Player/集成层映射，技能系统内部不硬编码键位。
- 当前尚无独立“攻击速度”或“施法速度”属性，技能时长完全来自各技能配置。

## 7. 当前尚未定案或值得讨论的问题

1. 反应倍率应在防御前还是防御后计算？当前为防御前。
2. 每层固定增加 30% 是否会让高层反应倍率增长过快？理论最大为 4 倍。
3. 形态是否只影响技能元素，还是应该进一步改变普攻、移动、被动或资源循环？
4. 水火是否需要独立立绘/动画，还是保留同立绘并加强粒子、轮廓和材质表现？
5. 两套独立技能槽最终应各有多少槽位？哪些技能允许跨形态共用？
6. 普通近战是否应携带当前形态元素？当前近战没有元素。
7. 是否引入攻击速度；若引入，它应缩放全部技能阶段，还是只缩放前摇和后摇？
8. 元素层数是否永久保留到被反应/死亡，还是需要自然衰减、持续时间或抗性机制？

## 8. 推荐网页端讨论提示词

```text
下面是一份当前可运行原型的玩法规则。请把“已实现事实”和“待讨论设计”严格分开，不要擅自增加土、电、Buff、装备等范围外系统。

请重点评审：
1. 水火 1:1 消耗、每层 +30% 的线性反应公式是否有良好的战斗决策空间；
2. 反应倍率放在防御前的优缺点；
3. 双形态独立技能槽应如何规划，才能避免只是换颜色；
4. 在不制作两套完整角色立绘的前提下，怎样强化形态辨识度；
5. 给出一版最小可玩的下一阶段技能配置，不要直接扩展成庞大系统。

请先指出现有设计的风险和矛盾，再提出不超过两个可执行方案，并说明推荐方案。
```
