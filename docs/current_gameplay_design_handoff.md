当前正式内容只配置水、火元素；底层切换契约读取有序可用元素列表，不把技能栏或切换逻辑绑定成只能有水火两项。

## 2. 元素附着、反应与伤害

元素是独立的底层战斗系统，不从属于某一个具体技能。

- 技能通过接受时快照声明本次攻击携带的元素和元素量。
- `ElementCarrier` 保存目标当前的水、火附着层数。
- `CombatReceiver` 统一提交伤害、元素附着和反应结果。
- 投射物、近战、范围和 Beam Delivery 只负责命中传递或目标空间行为，不拥有元素反应公式。
- 当前水、火各自最多附着 10 层；同元素命中累加至上限。
- 异元素命中按 1:1 消耗双方元素；未参与反应的来袭元素继续附着。

冻结的水火反应公式为：

```text
实际消耗层数 = min(目标已有相反元素, 本次来袭元素量)
反应倍率 = 1.0 + 0.3 × 实际消耗层数
```

| 实际消耗层数 | 反应倍率 |
|---:|---:|
| 0 | 1.0 |
| 1 | 1.3 |
| 2 | 1.6 |
| 3 | 1.9 |
| 10 | 4.0 |

水触发火和火触发水完全对称。当前冻结的伤害顺序为：

```text
技能伤害 = 接受时有效攻击力 × 技能伤害倍率 + 固定伤害加值
反应后伤害 = 技能伤害 × (1 + 实际消耗层数 × 30%)
减伤后伤害 = max(0, 反应后伤害 - 目标固定防御)
最终伤害 = 最后统一四舍五入
```

反应倍率位于固定防御之前。这是当前实现必须保持的冻结规则，不是尚待实现者自行选择的分支。

## 3. 共享技能栏与固定普通攻击

### 3.1 冻结栏位

- 全元素共享唯一一套 `ACTIVE_1～3 + PASSIVE_1～4`；主动/被动严格分区。
- 固定普通攻击位于这四个位置之外，不进入拥有技能库、随机奖励或共享配装。
- 元素变化不替换已装备内容；同一主动动作在所有元素状态下解析到同一技能 ID。
- `ACTIVE_1～3` 可装备主动或被动；`PASSIVE_1` 只允许被动，必须拒绝主动。
- 同一技能 ID 最多占用一个位置。
- 被动装在 ACTIVE 位置时持续生效，但对应动作不发起释放、不扣能量、不进入冷却。
- `0 主动 + 4 被动` 是合法配置，可以保存、载入、进入战斗、换层和完成房间；此时战斗依赖固定普通攻击与被动。

### 3.2 当前输入语义

- 三个独立主动动作始终请求 `ACTIVE_1`、`ACTIVE_2`、`ACTIVE_3`。
- 固定普通攻击使用独立动作，不占共享技能栏。
- 手动元素切换使用独立动作，不耗能、不占槽。
- `PASSIVE_1` 没有释放动作。
- InputMap 动作与 UI 键帽文本解耦；本文不把历史 `Q` 单槽或任何尚未验收的最终键帽布局写成当前规则。

### 3.3 被动生命周期

- 每个已装备被动只注册一次，与它位于 ACTIVE 还是 PASSIVE 位置无关。
- 换装以整体提交方式替换被动 Runtime，外部不能观察到新旧效果同时生效。
- 卸下、死亡、重生、换层、读档和新局重建均不得重复订阅或重复叠加。
- 三个 ACTIVE 位置若分别装备不同被动，三个被动各生效一次。

## 4. `CurrentElement` 与三类元素策略

玩家只有一个权威 `CurrentElement` 状态源。共享配装不会随其变化。

技能的行为类型与元素策略是两个正交维度：`ACTIVE / PASSIVE` 决定是否可释放；以下元素策略决定元素语义。

| 元素策略 | 接受释放时的行为 | 锁定元素 |
|---|---|---|
| `EXCLUSIVE_ELEMENT` | 接受事务内自动切到技能固定元素；失败不切换 | 技能固定元素 |
| `CURRENT_ELEMENT` | 不自动切换，读取提交瞬间的 `CurrentElement` | 提交瞬间元素 |
| `NEUTRAL` | 不自动切换 | `NONE` |

被动也声明元素策略，用于固定元素语义、条件和 UI 标识，但不会因此变成可释放技能。

`CurrentElement` 的冻结行为还包括：

- 手动切换按有序可用元素列表循环。
- `IDLE` 与 `RECOVERY` 可即时切换；`STARTUP`、`ACTIVE` 或暂不可操作时只保留最后一次手动切换请求。
- 死亡、换层和开始新局时清空缓冲切换。
- 元素变化事件携带旧元素、新元素、`MANUAL / SKILL_AUTO` 来源、单调递增序号和时间戳。
- 新旧元素相同是成功的无变化操作，但不发布变化事件。
- 遗物和被动可声明响应全部、仅手动或仅技能自动来源；重复序号不得重复触发收益。

## 5. 释放事务与锁定快照

主动释放遵循：

```text
REQUEST → VALIDATE / PREPARE → ACCEPT / COMMIT → RUNTIME → END
```

接受前必须完成技能身份、行为类型、控制状态、能量、冷却、可用元素、执行定义和生成配置验证。任一验证失败：

- 不切换元素；
- 不扣能量；
- 不开始冷却；
- 不生成攻击；
- 不播放成功或技能自动切换反馈；
- 返回结构化失败原因。

接受提交时，元素切换、能量、冷却和执行状态整体提交。`EXCLUSIVE_ELEMENT` 只有在释放被接受后才自动切换；领取或装备专属技能不会切换元素。接受后发生打断或取消，不回滚已经提交的元素变化。

每次接受都会锁定本次技能 ID、cast ID、元素、有效攻击力、伤害倍率、固定加值、攻击属性、Payload、实际能量消耗和该执行策略需要的生成参数。由此保证：

- `CURRENT_ELEMENT` 技能锁定接受瞬间的元素。
- `NEUTRAL` 技能及其攻击锁定 `NONE`。
- 已接受的投射物、范围攻击、Beam Tick、延迟攻击和多段攻击不会被之后的手动或自动切换污染。
- 已生成攻击不会重新读取实时攻击力、实时能量或实时 `CurrentElement`。

## 6. 当前正式技能内容

`RunContentCatalog` 是唯一正式静态注册源。正式目录包含一个固定普通攻击和八个可购买技能（四主动、四被动）。

### 6.1 固定普通攻击

#### `element_slash`

- 位于共享四槽之外，始终可用。
- 当前为 `NEUTRAL` 近战，伤害倍率 50%，元素附着为 0。
- 成功提交普通攻击命中时会发布类型化事件，供“不息”等被动消费。

### 6.2 八个可购买技能

| ID / 名称 | 类型与元素语义 | 当前正式规则 |
|---|---|---|
| `element_bolt` / 元素弹 | ACTIVE，`CURRENT_ELEMENT` | 初始拥有并默认装备 `ACTIVE_1`；消耗 10 能量；100% 攻击力伤害；附着 1 层；无冷却 |
| `elemental_fury` / 元素之怒 | ACTIVE，`CURRENT_ELEMENT` | 奖励池；至少 20 能量，接受时消耗全部当前能量；倍率、附着和半径由锁定能量快照决定 |
| `elemental_laser` / 元素激光 | ACTIVE，`CURRENT_ELEMENT` | 奖励池；每个完整 0.5 秒 Tick 消耗 5 能量，造成 50% 攻击力伤害并附着 1 层；Beam 穿透全部合法目标；引导期间允许移动 |
| `element_reclaim` / 回收 | ACTIVE，`CURRENT_ELEMENT` | 奖励池；不耗能、冷却 5 秒；原子消耗范围内全部匹配的当前元素层，每层理论恢复 5 能量；无匹配层或能量已满时原子拒绝 |
| `burning` / 燃烧 | PASSIVE，固定火语义 | 奖励池；每秒按目标当前火层数 × 5% 攻击力造成伤害；不消耗火层，不读取玩家 `CurrentElement` |
| `unending` / 不息 | PASSIVE，固定水语义 | 奖励池；固定普通攻击成功命中时，按目标水层数 × 1 恢复生命；不消耗水层，不读取玩家 `CurrentElement` |
| `passive_vitality` / 坚韧体魄 | PASSIVE，`NEUTRAL` | 仅梦尘购买；严格被动槽；常驻增加 20 点最大生命；无等级、无免费奖励、无默认槽、无世界 VFX |
| `passive_energy` / 元素储备 | PASSIVE，`NEUTRAL` | 仅梦尘购买；严格被动槽；常驻增加 10 点最大 SP；无等级、无免费奖励、无默认槽、无世界 VFX |

元素之怒的冻结快照公式为：

```text
伤害倍率 = 实际消耗能量 × 0.08
元素附着 = min(10, floor(实际消耗能量 / 20))
半径倍率 = 1 + floor(实际消耗能量 / 最大能量 × 10) × 0.10
```

`water_lance`、`fire_lance`、`passive_focus` 和 `passive_balance` 只保留为 legacy/test fixture，不进入正式 catalog。`passive_vitality` 与 `passive_energy` 已作为只可购买的正式被动注册，但不增加历史免费奖励投影。

## 7. 成长、奖励、遗物、商店与本局数据流

### 7.1 当前已实现的成长闭环

- 角色等级和属性点已经接入正式成长域；`PlayerGrowthAdapter` 将成长、被动和临时攻击修正投影到玩家运行属性。
- 主动或伤害型被动在接受或触发时捕获有效攻击力；后续成长变化不会回写已经生成的攻击。
- `CombatResult`、击杀和房间完成只在对应战斗提交成功后投影给成长域。
- 当前正式目录包含三件遗物资源。遗物通过窄 `GrowthEffectPort` 访问生命、能量和临时攻击修正，并以事件身份、来源过滤、冷却或单房上限防止重复收益。

本文只确认上述已经验收的数据流，不在此补写任务 12 尚未验收的等级、属性点或遗物最终 UI。

### 7.2 奖励与拥有技能库

- `RunContentCatalog` 统一提供 Gameplay 定义、奖励投影、初始拥有技能、固定普通攻击和遗物目录。
- 初始拥有 `element_bolt`，并默认装备到 `ACTIVE_1`；其余正式槽可为空。
- 第一战使用固定技能奖励；后续技能或遗物路线由 `RunDirector` 继续驱动。
- 首批其余五个可获取技能能够通过正式奖励进入拥有技能库，再经商店/配装事务装备。
- 领取技能只改变拥有状态；不会因领取、入库或装备而自动切换元素。

### 7.3 商店与共享配装

- 商店只编辑共享四槽 `ShopDraft`，不维护按元素拆分的两套当前配置。
- 草稿基于 Runtime Loadout revision 校验过期状态，并原子提交换装与被动替换。
- 换装后保存共享 `slot_id → skill_id` 快照。
- `0 主动 + 4 被动`、空槽、ACTIVE 装被动及 PASSIVE 拒绝主动均沿用第 3 节冻结规则。

### 7.4 `RunSessionHost` 的正式职责

- 每局由房间流程创建一个明确归属的 `RunSessionHost`；不使用永久全局单例保存本局状态。
- Host 从唯一 `RunContentCatalog` 建立或恢复本局的 `RunSession`、共享 `RuntimeSkillLoadout`、初始拥有库、奖励池和遗物目录，并连接 Player 的单一 `CurrentElement`。
- Host 作为集成边界，将提交后的元素变化、战斗结果、击杀和房间完成事件投影给 `RunSession`。
- 换装后由 `SharedLoadoutPersistenceAdapter` 保存共享快照；正式房间重载可恢复该快照。
- 敌人击杀使用内容 ID 与房间实例身份区分，保证同房间同名内容实例分别结算且不重复领取。
- 被动、遗物、死亡/重生、换层、读档和新局的重建均以本局 Host 生命周期为边界，不能重复注册。

简化后的权威数据流为：

```text
RunContentCatalog
  → RunSessionHost
    → RunSession（等级 / 属性点 / 拥有 / 奖励 / 遗物 / 房间进度）
    → RuntimeSkillLoadout（共享 ACTIVE_1～3 + PASSIVE_1～4）
    → Player CurrentElement（唯一状态源）

提交后的战斗 / 元素 / 击杀 / 房间事件
  → RunSessionHost
    → RunSession 与成长 / 遗物投影

奖励
  → 拥有技能库
    → ShopDraft
      → 原子换装与被动替换
        → 共享持久快照

成长 / 被动 / 遗物修正
  → PlayerGrowthAdapter
    → 有效运行属性
      → 接受时攻击快照
```

## 8. 旧配置迁移

历史上按元素保存的配置只作为一次性迁移输入，不是当前运行结构：

1. 读取旧存档记录的当前元素；无效时使用配置列表第一个元素。
2. 依次读取该元素及其他元素的旧主动位置。
3. 按顺序去重技能 ID，前三个进入共享 `ACTIVE_1～3`。
4. 超出的唯一技能仍进入拥有技能库，但不占用 `PASSIVE_1`。
5. 迁移成功后只保存共享 `slot_id → skill_id` 格式，不再双写旧格式。

正式 Player、技能控制器、商店和 Host 运行期间都只有一份共享 Runtime Loadout。

## 9. 当前表现与任务 12 边界

已经验收的表现事实：

- 六个可获取技能均已接入正式图标。
- 元素弹继续复用既有投射物场景与 SpriteFrames。
- 元素之怒、激光、回收、燃烧和不息已接入事件驱动的运行时 VFX。
- 动态元素 VFX 使用施法锁定元素，不读取播放时的实时 `CurrentElement`。
- 表现只观察 Delivery 或提交后事件，不拥有伤害、查询、费用、冷却、Tick、元素层数或碰撞规则。

仍然冻结、但不等于任务 12 最终界面已经验收的 UI 契约：

- HUD/配装需要固定呈现四个共享位置，状态变化不能造成布局跳动。
- 元素语义同时使用颜色和图形，不能只靠颜色。
- 专属、当前元素和无属性策略应有可区分标识。
- 手动与技能自动切换使用不同反馈；失败释放不播放自动切换成功反馈。
- `0 主动 + 4 被动` 需要明确提示战斗将依赖普通攻击与被动。

任务 12 的最终 HUD 布局、具体键帽、商店交互细节和反馈文案仍以其后续 Review 结果为准。

## 11. 推荐网页端讨论提示词

